## Discovered defect (release-blocking) — fixed on this branch

| Field | Detail |
|-------|--------|
| Where found | Manual smoke testing, "Pineton Council" scenario (Council = APPROVAL_TOP_N, 4 seats). |
| Symptom | With Space=3, Rooster=3 and Katie=2, Metta=2, Mort=2 tied for the final two seats, the count elected Space, Rooster, **Katie and Metta by candidate definition order** and silently dropped Mort. |
| Why it blocks release | Candidate definition order is administrator-controlled and arbitrary; using it to decide which tied candidate wins a real seat is not acceptable. |
| Fix | APPROVAL_TOP_N now walks score groups and elects a tied group only if it fits the remaining seats. The Space/Rooster pair is elected; the three 2-vote candidates are reported as **unresolved** for 2 seats, the contest/result is **incomplete**, and a runoff/admin resolution is required. No tied candidate is elected or dropped by order. |
| Coverage | New counting tests (cutoff tie larger than remaining seats, tie that exactly fits, tie below the cutoff, tie for the final seat, and the Pineton regression) plus in-game and witness formatter tests asserting the unresolved-tie display and that no tied candidate renders as elected. |
